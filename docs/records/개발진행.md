## 2026-10-21 · 계획 정비 UI 시안 (5/10단계)

최신 사용자 결정에 따라 미완료 작업은 최초 업무 기준일 이후 날짜 목록에 자동 이어 보이고, 전체 건수는 한 번만 센다. 날짜 선택을 화면 맨 위에 두고 날짜 칩·반복 날짜 추가를 제거했다. 과거 날짜를 선택해도 과거 상태를 복원하지 않고 현재 작업 상태를 보여준다. `npm test` 58/58, 앱 빌드·서버 빌드·공백 검사와 공개 시안 Playwright 흐름을 통과했다. 계획 입력은 탭 메모리뿐이며 계획 API/DB 쓰기·외부 연동은 없다. UI 승인을 기다리며 실제 저장 구현은 시작하지 않았다. 최신 공개 주소·절차·근거는 [이어보기 작업 기록](작업기록.md#planned-maintenance-carry-forward-20261021).

이전 검토 기록의 날짜 칩·미기록 날짜 수동 추가 동작은 후속 사용자 결정으로 폐기했다. 과거 검증 이력은 [날짜 UX 기록](작업기록.md#planned-maintenance-date-ux-20261021)에 남아 있다.

## 2026-10-21 · 계획 정비 설계 검토 (4/9단계)

공유 현황의 기존 `할당 작업`에 계획 수만 더하면 카드·목록이 달라지는 문제를 발견했다. 기존 비계획 버킷은 유지하고 계획·전체(비계획 할당, 선조치 후보고, 계획) 버킷을 별도로 설계했다. 계획 행의 제목은 사용자 결정에 따라 로그인 사용자 모두에게 보여준다. 날짜별 업무 목록과 전체 현재 상태 집계를 분리했다. 영구 삭제가 기존 공통 명령의 영수증·잠금 기록과 충돌해 계획 전용 API·영수증 저장 및 삭제 경계를 정했다. 날짜 정정·미래 날짜 금지는 당시 검토 제안이었고, 후속 사용자가 과거·미래 날짜 허용을 요청해 정정했다. 외부 체계의 하루 건수 자동 대조를 기능으로 해석한 것은 잘못이어서 제거했다. 작업반의 수동 확인·등록만 범위다. 아키텍처 웹은 이번 검토에서 제외했다. [상세 검토](작업기록.md#planned-maintenance-design-review-20261021).
