## 2026-10-24 · 스캔 OCR 실행·인식 품질 확인 · FR-042

- 범위·환경: 사용자 요청에 따라 합성 글자 이미지를 포함한 PNG와 이미지뿐인 PDF를 별도 로컬 검증 서버 8083에 올렸다. Homebrew Tesseract 5.5.3과 `eng`/`kor` 데이터로 서버를 시작했다. 공개 시연 서비스와 원본 업무 자료는 사용하지 않았다.

- 근거: 사용자는 기획·설계를 먼저 검토·승인하도록 요청했다. 업무 미결과 입력·권한 계약을 설계 때 닫지 못했다.
- 예상/실제: 필요한 업무 답변과 API 계약을 완성한 설계 검토 후 구현해야 하나, 구현 착수 후 분류·담당자·명부·CPCON 등의 결정을 질문했다.
- 조치: 사용자 지시로 제품 구현 중단·부분 소스 보존·앞선 질문 철회. 기존 결정·승인된 제안·기술 선택·실제 미결을 재분류하고 실제 미결만 기획 단계에서 질문한다. 새 설명 문서는 만들지 않는다.
- 추가 원인: 공개 CPCON 조사를 질문으로 넘겼고 임시 단계 A/B, 공지 숨김/게시 종료, 미완료 접수 전달을 제안해 사용자 부담을 늘렸다. 최신 지시에 따라 실제 군 업무/도메인만 질문하고 일반 설계 판단은 담당 에이전트가 한다. 공개 자료를 먼저 확인하고 요청하지 않은 기능은 추가하지 않는다.
- 재검사 기준: 요구사항·유스케이스·기능 명세·모듈·API에 같은 결정이 반영돼야 한다. 업무에 영향을 주는 결정 대기가 남으면 구현 범위와 제외 사유를 설계 검토에 명시한다. 설계 승인과 코드/검사 통과를 혼동하지 않는다.
- 마지막 상태: 기획·설계 재검토 중. 제품 실행·공개 배포 미검증.

관련 동작을 변경하기 전에 해당 사례의 근거와 검사를 읽고 다시 실행한다. 과거 통과는 현재 코드의 통과가 아니다. 제품 결함, 검증 도구 결함, 인공 오류를 구분한다. 완료 보고용 수치를 만들기 위해 미실행 값을 채우지 않는다.

새 사례에는 **발생 버전·종류 / 근거 / 예상과 실제 / 재현 명령·검사 / 증거 / 다음 실행 조건 / 마지막 결과·한계**를 남긴다. 기존 사례의 과거 결과는 보존하고 재실행 결과를 덧붙인다. 합격 사례 자체는 `docs/records/작업기록.md`의 해당 변경에 출처·상태와 함께 남긴다.

- 후속 사용자 정정: `59b9aaa`에서 복구했다고 주장한 웹은 사용자가 사용한 원본이 아니었다. 6조합 통과가 원본 일치까지 검증한다는 결론을 철회한다. 사용자 직접 첨부와 파일을 읽었던 전체 기록을 대조한 뒤 `docs/spec/아키텍처설계.html`로 복구했다. 앞으로 원본 파일 또는 첨부 근거와 실제 화면을 먼저 확인한다. 세부 출처·검증 결과는 작업 기록의 원본 복구 절을 따른다.

## 설계 개정에서 놓친 최신 결정과 첨부 계약

- 종류·버전: `fed2b10` 이후 설계 개정 중 발생한 문서 계약 불일치. 제품에 구현된 결함이 아니다.
- 근거: 사용자의 반장 지정 제거와 BNOC 공지게시판·첨부문서 결정. 작업 기록 첫 절의 답변 원문을 따른다.
- 발견·수정: reviewer가 개발명세서 두 표에 남은 반장 입력을 찾았다. verifier가 요청에만 파일을 연결하던 설명과 대상 종류 없는 업로드 함수를 찾았다. 반장 입력 제거, 요청/공지별 업로드 대상과 권한, 저장된 연결을 기준으로 한 다운로드로 문서·함수 계약·웹을 맞췄다.
- 재검사: `node scripts/verify-design.mjs --static`의 문서/웹 계약 대조와 독립 의미 검토. 첨부·공지·배정 계약 변경 시 최신 사용자 원문과 서버 API, 모듈 입출력을 함께 대조한다. 구현 단계에는 다른 대상의 파일을 연결하거나 다운로드하는 우회도 실제 서버에서 검사한다.
- 마지막 결과: 정적 검사와 독립 재검토 통과. 검토 (비공개 원본 이력: `../../runtime/evidence/backend-architecture-design-20261013/review.json`)·검증 (비공개 원본 이력: `../../runtime/evidence/backend-architecture-design-20261013/verifier.json`). 현재 결과는 실제 업로드/다운로드 실행 증거가 아니다.

## 설계 검사와 오류 주입 증거 누락의 재발

- 종류·버전: `fed2b10` 이후 `scripts/verify-design.mjs` 개정. 경계·분류의 인공 오류 검사이며, 증거 누락은 검증 도구의 실제 결함이다.
- 기대: 정상 설계는 통과하고 서버 업무의 브라우저 이동, BNOC 필수 분류의 선택화는 각각 거절한다. 주입한 변경 행·실행기 버전·원본 불변·임시 복사본 정리를 추적할 수 있어야 한다.
- 실제: 처음 새 검사는 과거 HTML에 없는 `DOMAINS`를 읽어 실패했다. 이를 오류 탐지로 세지 않고 수정한 뒤 의도한 `BACKEND_BOUNDARY_REQUIRED` 실패를 확인했다. 후속 verifier가 실제 주입 diff·검사기 해시 누락을 찾았다. 이전 일정 실험에서 지적된 증거 보존 누락이 새 실행기에도 재발한 사례다.
- 수정·재현: `node scripts/verify-design.mjs --fault-check`. 두 복사본 모두 의도한 assertion에서 거절됐고 각 실제 diff, 원본/변형본/검사기 SHA256, 임시 파일 정리 결과를 저장했다. 최종 증거 (비공개 원본 이력: `../../runtime/evidence/backend-architecture-design-20261013/fault-check.json`). 다음 설계 검사·오류 주입 실행기 변경에도 저장된 실제 diff와 버전을 직접 확인한다.
- 기존 실패 재사용: 작업 일정 실험도 다시 실행해 정상 27/27·3/3, 오류 복사본 27/27·2통과/1의도한 실패를 재현했다. 결과 (비공개 원본 이력: `../../runtime/evidence/backend-architecture-design-20261013/sensitivity/summary.json`)·diff (비공개 원본 이력: `../../runtime/evidence/backend-architecture-design-20261013/sensitivity/mutation.patch`). 실제 서버 권한, 전체 오류 예방률을 입증하는 결과는 아니다.

## CPCON 누락과 모의 연동 계약 누락

- 종류·버전: `42a737e`의 설계 누락. 사용자가 CPCON 부재와 실제 SSO·GPS 연결 불가 조건을 지적했다. 당시 요구사항에 CPCON을 예시/선정 대기로 남겼지만 기능 명세·모듈에는 없었다. 제품 결함이나 AI 선제 발견이 아니다.
- 기대·정정: 공고 R02의 CPCON을 독립 기능으로 추적하고 모의 인증/상황 제공자와 실제 BNOC 세션·권한·수집·저장을 연결한다. CPCON 단계·적용 범위를 GPS에서 복사하지 않으며 실제 연동 미확정을 대회 설계 중단 조건으로 쓰지 않는다. 기존 핵심 문서·웹에 반영했다.
- 재검사: `node scripts/verify-design.mjs --static`, `--fault-check`, 브라우저 실행. 새 기능 추가·공고 대응·외부 제공자·인증 경계 변경 시 공고 항목과 실제 기능/모듈 연결을 함께 대조한다. 단순 명칭의 존재만으로 공고 충족을 판단하지 않는다.
- 실제 결과: 기존 HTML에서 `CPCON_FUNCTION_REQUIRED` 실패, 개정본 정상 통과. CPCON 삭제 복사본과 운영 모의 인증 허용 복사본은 지정 assertion에서 실패했고 기존 서버 경계/분류 오류도 재검사했다. 4건 주입 diff·해시·정리 (비공개 원본 이력: `../../runtime/evidence/external-integration-design-20261013/fault-check.json`).
- 독립 검토 발견: 로그인 요청이 시작 브라우저와 결합되지 않은 조건, 첫 수집 실패를 미수집으로 표시한 조건, 인증 시작/완료 API의 모듈 연결 누락을 수정했다. 다음 인증·수집 계약 변경 시 이 조건을 재대조하고 구현 단계에는 다른 브라우저의 유효 확인표 제출·첫 수집 실패를 실제 서버 시험으로 확인한다. 현재는 설명 검사다.
- 마지막 상태: 두 브라우저·세 너비 통과, 독립 재검토 잔여 지적 없음. 실행 범위 (비공개 원본 이력: `../../runtime/evidence/external-integration-design-20261013/verification.json`)·검토 (비공개 원본 이력: `../../runtime/evidence/external-integration-design-20261013/review.json`)·검증 (비공개 원본 이력: `../../runtime/evidence/external-integration-design-20261013/verifier.json`). 실제 공군 호환·제품 기능·최종 공고 충족·사용자 승인은 미검증이다.
