## 2026-10-29 · UC-013 계획 편집의 자동 재조회 입력 대상

기존 NFR-010/UC-013에 적용하는 AI 사용성 보완이다. 기존 문서에 재조회 전후 동일 초점·caret의 직접 명문이 있었다고 소급하지 않는다. JAR6044의 실제 GET 보류/해제 뒤 날짜에 친 숫자가 제목에 붙고, 제목 중간 caret4에서 칠 문자가 끝에 붙는 반례와 무보류 정상 대조를 확인해 다음 기준을 채택한다.

- 명시 수정 시작은 기존 제목 첫 초점을 유지한다. 같은 편집의 자동 재조회 DOM 교체는 사용자가 선택한 입력 대상과 제목의 문자 선택 위치를 보존한다. 뒤따르는 실제 키를 다른 필드/다른 제목 위치로 보내지 않는다.
- 편집 밖의 유효한 조작·실제 로그인 dialog·inert 배경·비활성 문서가 우선이다. 오래된 복원 요청으로 초점을 빼앗거나 이후에 지연 적용하지 않는다. 취소·다른 편집 수락·날짜 이동 수락·저장 성공 등 기존 명시 종료는 이전 초점 기록을 정리한다.
- 기존 정상 inline/단일 편집기·dirty/폐기 확인·시작 revision·현재 대상 확인·저장/권한·생성 복구는 유지한다. native date 내부 연·월·일 구간과 실 OS/전수 접근성·사람 효율은 별도 관측 없이 보존됐다고 하지 않는다.

## 2026-10-29 · 기존 계획 편집의 재인증·재조회 보호

FR-008/NFR-005·007/UC-013의 기존 입력 유지·오래된 편집 거절을 구체화한다. 실제 격리 반례는 재조회 대기 중 확인 없는 이동과, 별도 세션 수정 뒤 새 조회 revision이 옛 입력에 결합된 저장이다. 편집 시작 기준 고정은 기존 문구의 AI 기술 해석이며 새 사용자 결정으로 표시하지 않는다.

기존 계획의 미저장 편집은 조회 대기·대상 부재만으로 폐기되지 않는다. 현재 목록과 별도로 입력과 이동 안내를 유지하고, 미변경 편집은 추가 확인하지 않는다. 명시 취소·저장 성공·날짜 이동의 폐기 동의로 편집 문맥을 끝낸다. 기존 draft는 시작 원문과 revision으로 저장하고 충돌 시 입력을 유지한다. 최신 값 확인 뒤 새 편집은 기존 취소/재편집 조작으로 구분한다.

현재 작업반 목록·쓰기 권한을 유지한다. 이전 반 항목을 새 반 목록에 삽입하거나 권한을 복원하지 않으며, 현재 수정 대상을 확인할 수 없을 때 저장하지 않는다. UC-013의 생성 재시도 OPERATION_NOT_AVAILABLE 뒤 키/제목 정리와 App 전환 정책은 그대로다.

편집 종료 조건은 조회 갱신만으로 자동 폐기하지 않는다는 뜻이다. 기존 App 이동의 폐기 동의·계정 전환 초기화는 유지한다. 명시한 날짜 이동은 clean이면 확인 없이, dirty이면 폐기 동의를 받은 뒤 편집 문맥을 끝낸다. 다른 항목을 수정하려면 dirty 내용의 폐기를 확인하고, 취소하면 기존 입력을 유지하며 clean 전환은 추가 확인하지 않는다. 조회 대기·오류·대상 미확인은 저장 버튼과 handler에서 함께 막되, 같은 대상의 최신 revision이 다르다는 이유만으로 시작 revision의 PATCH/서버 충돌 검사를 생략하지 않는다.

## 2026-10-28 · 팀원 검토에 따른 신청·조회 흐름 개선

최신 [사용자 결정](요구사항.md#team-feedback-20261028)에 따른 UC-028/001/008/009/010/011/018/020/026 후속 개정이다.

1. 요청자는 빈 새 신청 또는 눈에 보이는 이전 신청 불러오기를 선택한다. 재사용 후보는 본인이 직접 작성한 요청만 제공하고 선택 시 원본을 재조회한다. 이번 첨부/일정은 새로 입력한다.
2. 목적·대상·대상 정보·연락처를 순서대로 작성한다. 대상 정보에서 선택 추가정보/첨부를 열 수 있다. 상단의 지난 단계를 클릭하거나 이전으로 이동해도 입력은 남는다. 바로 다음 질문을 다시 확인하며 전진하고 과거 완료 여부로 건너뛰지 않는다.
3. 최종 확인은 내용 확인·선택 첨부·신청 등록을 중심으로 표시한다. 목적/수량/연락처는 상단 해당 단계에서 바꾼다. 첨부를 올린 직후 정식 접수 전에도 본인 파일의 사진/PDF/HWP/DOCX 등 지원 원본을 열고 닫아 신청으로 돌아온다. 회의 필수 의뢰서·오류·미확정 등록 잠금은 유지한다.
4. 등록 후 목록은 요청 번호 내림차순을 유지한다. 요청자 상세는 현재 담당 부서의 상태·대표전화·담당자만 보이며 반환된 부서 카드는 숨긴다. BNOC/작업반의 반환 처리/이력은 보존한다.
5. 관리자는 기존 부서별 작업 현황에서 부서 대표전화를 수정·저장한다. 다른 역할은 수정할 수 없다. 초기 임시 번호를 실제 번호로 정정할 수 있으며 재시작 후 유지한다.
6. 부서 현황에서 부서를 검색하면 합계·상세 목록·부서별 진행 상황이 동일한 적용 부서만 보여 준다. 조회 실패 시 마지막 성공 결과/조건을 유지하고 전체로 검색하면 모든 부서를 복원한다.

<a id="adaptive-intake-20261027"></a>
## 2026-10-27 · UC-028 적응형 복수 대상 신청

근거 [FR-056](요구사항.md#adaptive-intake-20261027). 주체는 기존 요청자/BNOC이며 실제 요청자 연결과 등록자 구분을 유지한다.

1. 첫 질문은 고장·신설·지원·기타 네 목적만 제공한다. 고장/신설/기타는 장비 경로로, 지원은 회의 지원/장비 지원/대여/점검/이전 선택으로 이어진다. 장비 경로에서만 장비 이름 또는 +를 누른 만큼 선택하며 −로 줄이고 0에서도 조작 위치는 유지한다. 회의 경로에는 장비·수량을 표시하지 않는다. 처음 선택한 작업을 새 대상에 적용하며 동일한 작업 질문을 반복하지 않는다. 목적/경로를 바꿔도 작성 중 텍스트·수량·각 경로의 첨부를 보존하되 정식 제출은 활성 경로만 포함한다. 기존/대상별 다른 작업을 첫 목적 선택 때문에 일괄 덮어쓰지 않는다.
2. 기본 경로에서 작업(이미 선택한 새 대상은 생략)·위치·증상/요청 내용의 필수 질문만 답한다. 한 대상의 필수 답변을 마치면 별도 대상 확인 클릭 없이 다음 미완성 대상이나 연락처/최종 확인으로 이어진다. 기술 선택정보는 기본 경로에서 건너뛰기 클릭을 강제하지 않으며 최종 대상의 추가·수정에서 필요한 항목만 단일 질문으로 연다. 여러 값을 아는 사용자는 마지막 필수 질문에서 장비 정보도 함께 입력을 선택해 현재 대상의 미응답 선택정보만 이어 답할 수 있다. 이 선택은 다음 대상에 이어지지 않는다. 신설에서는 모델명을 묻지 않는다. 선택형은 즉시 다음 질문, 한 줄 입력은 계속/Enter, 여러 줄 내용은 계속/Ctrl+Enter로 진행하고 Enter 줄바꿈은 유지한다. 뒤로 가도 입력은 유지된다.
3. 같은 정보는 선택 수량 전체에 쓴다. 다른 종류의 위치 질문에서는 이전에 확정한 위치를 명시적으로 선택해 재사용할 수 있으며 기존/개별 위치를 자동 덮어쓰지 않는다. 일부 망/전화 종류/위치가 다르면 대상 수를 나누고 차이만 수정한다. 여러 종류는 선택한 순서대로 작성한다. 분할·취소·삭제·뒤로 재진행에서도 총수량과 각 정보가 일치한다.
4. 필요한 첨부를 실제 업로드한다. 회의의 기존 필수 의뢰서를 빼면 정식 제출하지 못하지만 초안으로 저장할 수 있다. 연락처·실제 요청자 계정과 기존 선택 정보는 필요한 순서에 작성한다.
5. 최종 요약에서 작성한 값만 확인하고 대상의 추가정보/첨부/분할/제외를 열 수 있다. 필드 정정은 필요한 질문만 마친 뒤 출발 요약으로 복귀하며 이미 유효한 연락처/요청자를 재질문하지 않는다. 기존 신청 명령으로 요청 1건을 저장한다. 새로고침·서버 재시작 뒤에도 대상과 첨부가 보존된다. 불명확한 접수 결과는 입력/뒤로/분할/초안 변경을 잠그고 같은 제출로 복구한다.
6. 저장된 복수 대상은 현재 상세 권한으로 조회하고 기존 수정 가능 상태/버전에서 정정한다. 재사용은 허용된 대상 내용만 새 초안으로 가져오며 일정·첨부·신원·번호·업무 상태·이력·제출키를 복사하지 않는다.

기존 단일 신청과 완료 후보고는 해당 계약을 유지한다. 복수 접수 대상 때문에 작업반 작업을 늘리거나 완료 단위를 바꾸지 않는다.

<a id="uc-026"></a>
### UC-026 중앙 병력·근무표 · R03·R05

BNOC 행정병이 간부·병사의 소속·계급·이름·군번과 선택 군내전화를 중앙 명부에 등록·정정한다. 휴가·외박·출장·파견·교육·기타의 시작일~종료일을 한 번 등록하고 변경 때 정정한다. 조회 날짜에 겹치는 각 사람을 한 번만 결원으로 세며 `총원=현재원+결원`을 보여준다. BNOC는 당직사관·정보통신대대 일직사관 월표를, 각 작업반은 자기 반 야간 근무 월표를 중앙 명부에서 필요한 1명 또는 여러 명을 선택해 작성·정정한다. 주·야간과 시각 입력은 없다. 당직사관과 정보통신대대 일직사관은 24시간 근무자로 해당 날짜의 오늘 근무자 현황에도 자동 포함한다. 모든 로그인 역할은 오늘 근무자를 기본으로 보고 일·주·월 보기에서 날짜별 근무자를 확인한다. 읽기 전용 역할과 작업반의 타 범위 조회는 날짜·자리·작업반과 근무자의 계급·이름만 받으며, 편집 범위에서는 저장에 필요한 인원 참조·명부 상태·부재 충돌 boolean을 더 받는다. 군번·연락처·부재 종류·사유는 근무자 조회에 포함하지 않는다. 일반 요청자는 중앙 명부·부재·병력 현황을 볼 수 없다.

일별 보기에서 선택 날짜의 당직사관·정보통신대대 일직사관·각 작업반 야간근무자를 확인한다. 주별·월별 보기에서 날짜를 고르면 해당 날짜의 편성을 확인한다. 아직 입력되지 않은 일정은 `등록된 편성 없음`으로 표시하고 근무자가 없다고 단정하지 않는다. 읽기 전용 사용자는 조회 과정에서 명부 데이터를 받거나 일정을 변경하지 못한다.

월 근무표에서는 한 줄에 `YYYYMMDD 계급 이름`을 적은 여러 행을 붙여 넣어 한 번에 추가할 수 있다. 현재 선택한 근무 자리(작업반은 자기 반 야간 근무)에 적용한다. 각 날짜·계급·이름이 현재 월과 편성 가능한 중앙 명부 인원 한 명에 정확히 일치하고 해당 날짜 부재가 없는지 전체 행을 먼저 확인한다. 잘못된 행이 하나라도 있으면 아무 행도 추가하지 않는다. 기존 편성은 보존하고 이미 들어 있는 같은 인원은 중복 추가하지 않는다.

작업반이 작업 일정과 담당자를 정할 때 같은 중앙 명부의 자기 반 인원 목록을 연다. 여러 예정 구간 중 하루라도 부재 기간이 겹치는 사람은 사유와 함께 목록에 남지만 선택할 수 없다. 일정이 아직 없을 때의 인원 선택은 기존대로 허용하며, 이후 일정을 저장할 때 다시 검사한다. BNOC가 나중에 부재를 기록해 이미 저장된 근무표·담당자와 충돌하면 원 기록을 지우지 않고 담당 화면에 충돌을 표시한다. BNOC 또는 해당 작업반이 근무표·작업 일정·담당자를 정정한다. 요청자는 본인 요청 상세에서 선택된 담당자의 계급·이름·등록된 군내전화만 본다. 다른 사람 명부, 군번, 부재 사유, 개인전화는 받지 않는다.

<a id="uc-027"></a>
### UC-027 정비 달력·진행 알림 · R04·R07·R08

로그인 사용자는 일·주·월 달력에서 허용된 배정 작업·후보고 기록과 계획 정비를 함께 본다. 계획은 날짜 항목으로 보여 시간 칸에 임의 시각을 만들지 않는다. 계획 제목·담당 부서·상태는 모든 로그인 사용자가 보며 여러 날짜에 보여도 집계는 한 작업이다. 상세 이동 때는 기존 권한을 재검사한다.

작업반이 여러 반에 배정된 요청의 자기 작업 상태를 저장하면 전체 요청 상태가 그대로여도 계정 연결 요청자에게 그 반의 진행 알림을 한 번 보낸다. 예정일·담당 인원만 바꾼 저장에는 새 알림이 없다. 완료 선조치 후보고를 등록할 때는 작업반에 허용된 활성 요청자 계정 목록에서 필수 선택하고 BNOC와 그 계정에 알린다. 이름 텍스트만으로 후보고를 제출할 수 없다. 이전 실패·재시도는 중복 알림을 만들지 않는다.

## 2026-10-25 · 신규 신청 임시저장 흐름

요청자/BNOC는 신규 신청 화면에서 미완성 입력도 `임시저장`한다. 성공한 마지막 저장본만 접속 종료 뒤 남으며 이후 편집은 다시 저장해야 한다. 업로드 완료·임시저장 성공에 포함된 파일만 보존한다. 신청 메뉴 재진입/재로그인 뒤 저장본 존재를 안내하고 `임시저장 불러오기`를 누를 때 현재 입력을 확인해 교체한다. 자동 복원으로 빈 신청이나 이전 요청 재사용 초안을 덮어쓰지 않는다.

`임시저장 삭제`는 명시적 확인 뒤 서버 초안만 삭제하고 현재 화면 입력은 유지한다. 창 닫기/로그아웃은 서버 저장본을 삭제하지 않는다. 다른 계정/역할에서는 원래 초안을 보여주지 않는다. 다른 탭의 저장·삭제·제출로 시작 버전이 달라지면 현재 입력을 유지하고 충돌을 안내한다. 재인증 뒤 같은 계정은 같은 입력·시작 버전·제출 식별값으로 재시도한다. 정식 등록 성공 시 제출에 연결된 초안만 함께 소비하며 실패 시 초안을 남긴다. 팀 후보고·요청 수정·공지 작성은 기존 흐름을 유지한다.

## 2026-10-25 · UC-001·UC-008 이전 요청 불러오기

본인 직접 신청의 상세에서 `새 요청으로 불러오기`를 누른다. 저장된 원본을 현재 권한으로 다시 조회하고 재사용 가능 여부를 검사한 뒤 새 신청 초안을 연다. 미저장 상세 편집값은 가져오지 않으며 이동을 취소하면 상세와 입력을 그대로 유지한다. 분류·내용·장소 등 허용 값만 채우고 일정·첨부를 비워 새로 입력하도록 안내한다. 제출 전에는 요청·이력·알림을 생성하지 않으며 제출 성공 때 새 번호의 대기 요청을 만든다. 실패·응답 불명확 시 기존 신청서의 동일 제출키/입력 보존 규칙을 따른다. 초안은 메모리 한정이고 URL·브라우저 저장소에 넣지 않는다. 화면을 나가거나 로그아웃/다른 계정으로 전환하면 초안을 정리한다.

## 2026-10-25 · UC-018·UC-020 원본 미리보기 정정

최신 사용자 요청에 따라 첨부의 `문서 보기`는 HWP·PDF·DOCX·PNG/JPEG 원본을 기본으로 보여준다. 회의 첨부에도 현재 조회권한을 검사한 뒤 원본 보기를 허용하며, 기존 다운로드 전용·미리보기 금지 단계는 이 결정으로 대체한다. 회의 첨부와 일반 DOCX에는 서버가 추출한 본문/메타데이터를 표시하거나 검색하지 않는다. 분석 제외 상태를 빈 본문 화면으로 오인하게 하지 않고 원본 보기와 분석 여부를 구분한다. 렌더 불가·손상 문서는 구체 오류 및 원본 다운로드를 제공하며, 닫으면 이전 문서 표시·자원을 정리하고 초점을 복원한다.

## 설문 기반 추가 흐름 · 2026-10-22 설계 초안

설문 기반 추가 기능은 [FR-038, FR-041~042](요구사항.md#survey-enhancements-20261022)다. FR-039·FR-040은 철회했다. UC-019는 설문 추가 기능이 아닌 별도 권한 정리로 둔다.

### UC-014 상태와 현재 단계 이해

1. 사용자가 목록/상세의 상태 배지에 마우스를 올리거나 Tab으로 초점을 준다.
2. 2026-10-24 사용자 후속 결정에 따라 hover/focus에서는 배지에 이미 보이는 현재 상태/단계 도식을 반복하지 않고 담당 부서와 공식 대표번호를 본다. 요청 전체 배지는 현재 유효 담당 부서를 모두, 개별 작업 배지는 해당 작업 부서를 표시한다. 선조치 후보고는 수행 부서로 표시해 BNOC가 배정한 것으로 보이지 않게 한다. 번호는 공식 부서 연락처 자료에서 가져오며 요청자·개인·정비대상자 번호로 대체하지 않는다. 번호 자료가 없으면 임의 번호를 만들지 않고 `대표번호 미등록`으로 표시한다.
3. 안내 위로 마우스를 옮겨도 읽을 수 있고 Escape로 닫는다. 화면 가장자리에서는 안내 위치를 바꿔 잘리지 않게 한다.
4. 상세에서는 단계 도식을 넓게 본다. 중복 상태 배너·역할 설명·범례를 생략한다. 문서 대기·반환·취소·기각·후보고는 상태명과 짧은 한 줄만 보여주고 일반 도식을 넣지 않는다. 부서 진행은 요청 단계와 구분한다.
5. 요청자에게 내부 반환 사유를 공개하지 않고 필요한 경우 재배정 확인 대기처럼 일반화된 맥락을 보여준다.

작업반이 자기 반의 개별 작업 상태를 볼 때는 그 작업의 상태 자료로 3단계를 안내한다. 내부 `작업 중`은 `작업 준비`로 표시하되 요청 전체 `작업 중`은 유지한다. 요청 상태에서 개별 작업 상태를 추정하지 않는다.

실제로 거치지 않은 단계·시각은 만들지 않는다. 일부 반 완료는 전체 완료율로 표현하지 않는다. 과거 참여 작업은 현재 부서 진행과 구분한다.

### UC-015 요청 입력 확장 · 철회

2026-10-23 사용자 결정으로 유형별 별도 필수 입력과 한 요청의 복수 대상 기능을 제외한다. 기존 신청서와 요청 내용 입력 흐름을 유지하며 신규 정책 버전·대상 행·구조화 `taskInfo`를 만들지 않는다. 팀원 main의 기존 신청 동작과 저장 규칙은 이 시안 철회로 변경하지 않는다. UC-015 식별자는 철회 상태로 보존한다.

### UC-016 자원 관리·조회 · 철회

2026-10-22 사용자가 전한 유선반 병사 인터뷰 의견에 따라 가용 자원 기능을 철회했다. FR-040·UC-016·SR-BE-039는 철회 식별자로 보존하며 번호를 재사용하지 않는다. 자원 등록·수정·조회·비활성/복원과 신청 중 조회 흐름을 제공하지 않는다.

### UC-017 요청·첨부 내용과 키워드로 찾기

1. 허용된 신청 목록에서 검색어와 기존 조건을 입력한다. 타이핑 중 결과는 바뀌지 않는다.
2. 검색/Enter를 실행하면 권한 범위 안에서 요청 본문·기존 분류 정보·현재 연결된 첨부의 추출 본문/메타데이터를 검색한다.
3. 결과에서 요청 요약과 일치 출처·문맥을 확인한다. 첨부 문맥을 선택하면 권한을 다시 확인한 뒤 해당 본문 블록이나 문서 정보 항목으로 이동한다.
4. 조건 변경 전/후, 결과 없음, 실패·마지막 성공 결과를 기존 조회 맥락으로 구분한다.

완료·취소 요청도 기존 조회 조건에 따라 검색한다. 여러 첨부가 일치해도 요청 한 건으로 표시한다. 다른 사용자 요청의 존재·파일명·본문·건수는 노출하지 않는다. 분석 중·실패 파일 때문에 요청 전체를 숨기지 않고, 분석 상태에 따라 본문 검색이 아직 끝나지 않았음을 구분한다.

검색은 신청 목록에서 실행한다. 일정 카드·전체 공유 작업 현황에는 본문/문서 문맥을 옮기지 않는다. 일정 카드의 기존 상세 링크로 이동한 뒤 해당 요청 권한을 다시 확인해 첨부를 연다. 계획 정비는 요청 검색에 섞지 않는다.

### UC-018 첨부 보기와 추출 정보 확인

1. 요청 상세 또는 권한이 있는 이력의 HWP/PDF 첨부에서 원본 보기나 추출 정보 보기를 선택한다.
2. HWP는 브라우저 내 페이지 렌더러로 원본 레이아웃을 보여주고, PDF는 원본 페이지를 인라인으로 보여준다. 원본 다운로드도 제공한다.
3. 텍스트 본문·문단/표 블록·제목/회의명/일시/장소 후보와 각 값의 원문 근거를 확인한다. 검색 결과에서 열었으면 일치 위치를 표시한다.
4. 분석 중에는 상태와 갱신 동작을, 일부 추출·실패·암호화·손상·텍스트 없음은 해당 상태와 다운로드/재시도 가능 여부를 안내한다. 스캔 PDF는 OCR하지 않으며, 원본 보기·다운로드는 유지한다.
5. 화상회의·일반회의 지원 첨부는 보안 경계에 따라 분석·내용 검색·인라인 보기 없이 권한 다운로드만 제공한다.

본문 추출은 첨부 연결 저장 뒤 비동기로 진행하며 신청 저장을 기다리게 하지 않는다. OCR은 실행하지 않는다. 텍스트가 없는 스캔 PDF는 `no_text` 상태로 두고 첨부 내용 검색에 포함하지 않는다. 기존 허용 첨부 형식의 업로드·다운로드 동작은 유지한다. 세션 만료·로그아웃·권한 변경 시 뷰어와 추출 정보의 현재 권한을 재확인한다.

### 연계된 기존 권한 정리 · UC-019

작업반 역할은 자기 반 명부·병력·야간 정보를 관리한다. 지정 담당자 여부를 선택하거나 별도로 부여받지 않는다. 소속·작업반은 서버의 현재 인증 정보로 판정한다. BNOC·요청자·권한 관리자에게 자기 반 작업 수행/현황 수정 권한을 자동 부여하지 않는다.

이 관리 권한 정정은 자기 반 일정 조회·작업 저장, BNOC 배정, 전체 공유 현황의 기존 권한을 변경하지 않는다.

데모 전용 통합 작업반 로그인과 가상 계정/권한 화면을 제거하고 기존 로그인·계정 관리 화면을 그대로 사용한다. 내부 행정병·작업병 로그인 구분을 만들지 않는다. 서비스 권한 관리자 자체는 유지하며 기본 역할·작업반·활성 여부를 관리한다. 과거 지정 담당자 플래그만 가진 요청자는 작업반 권한으로 자동 전환되지 않는다. 기존 기록의 작성자 표시와 인원 참조는 보존한다. 작업반에 연결되지 않은 과거 부서는 현재 자료를 보존·조회하며 새 관리 주체를 임의 생성하지 않는다.


### 팀원 사용 피드백 흐름 · 2026-10-24

#### UC-020 회의 지원 신청

요청자는 회의 지원에서 화상회의·일반회의·기타 중 하나를 선택한다. 화상회의면 KJCCS·AFCCS·웹미팅 중 하나를 고른다. 화상회의와 일반회의는 각 유형에 맞는 지원 의뢰서를 첨부해야 제출할 수 있다. 기타는 이 첨부를 요구하지 않는다. 보안 양식 원본은 기존 권한에 따라 다운로드할 수 있지만, 화상회의·일반회의 요청에 연결된 첨부는 종류와 관계없이 본문을 추출·검색·미리보기하지 않는다. 기존 분석 본문과 메타데이터도 제거하며 원본 파일은 보존한다. 기존 요청에는 첨부를 소급 요구하지 않는다.

#### UC-021 개인전화번호 입력·조회

요청자는 군내전화번호 외 개인전화번호를 선택 입력한다. 요청자 본인·BNOC·현재 유효 배정 작업반만 요청 상세에서 볼 수 있다. 공유 작업 현황·일정·다른 작업반에는 표시하지 않는다.

#### UC-022 대리 등록 요청을 실제 요청자가 수정

BNOC는 대리 등록 때 활성 요청자 계정을 선택한다. 시스템은 그 계정을 실제 요청자로 연결하고 BNOC를 등록자로 별도 보존한다. 연결된 요청자는 기존 수정 조건 안에서 대리 요청을 수정할 수 있지만 요청자 계정·등록자·BNOC 전용 필드는 바꿀 수 없다. 과거 계정 미연결 요청은 이름이나 연락처로 자동 연결하지 않는다.

#### UC-023 BNOC가 담당 밖 요청을 기각

BNOC는 아직 배정 작업이 없는 대기·문서 대기 요청을 사유와 함께 기각한다. 시스템은 요청 상태·사유·이력·요청자 알림을 함께 저장한다. 요청자는 상세에서 사유를 확인한다. 작업이 배정됐거나 다른 상태면 기각을 거절한다. 기각 후 요청은 재개·배정·수정·취소할 수 없다. 작업반 반환과 다른 상태다.

#### UC-024 선조치 후보고의 24시간 입력

작업자는 실제 시작·완료 날짜와 HH:mm을 24시간제로 입력한다. 날짜별 순서 검사와 기존 UTC 저장은 유지한다. 요청 희망 일정의 오전·오후 선택은 바꾸지 않는다.

## 1. 로그인과 역할

각 부서의 지정 담당자는 개인 계정의 소속과 현황 관리 권한으로 식별한다. 같은 부서 비담당자는 명부/현황을 수정하지 못한다. 현황 관리 권한으로 BNOC 배정·작업 수행 권한을 자동 얻지 않으며 필요한 권한의 별도 겸임은 막지 않는다. 상단·편집 화면에 소속과 담당 범위를 표시하고 권한 관리자 단독 계정에 허용되지 않은 현황 메뉴를 표시하지 않는다.

**사용자 결정:** 공군 SSO, 회원가입 없음. **기존 확정:** 권한 관리자가 역할·작업반 권한을 부여·회수하고 이력을 남김. 자기 권한 상승 금지.

**공개 대회 시연:** 다른 컴퓨터의 브라우저에서도 서비스 HTTPS 주소로 접속하고 같은 Origin의 `/identity` 팝업에서 역할명으로 모의 인증한다. 확인표 검증·GPS/CPCON 수집은 서버와 별도 모의 제공자의 비공개 연결로 처리한다. 브라우저를 `127.0.0.1`의 제공자로 보내지 않는다. 공개 시연은 별도 빈 자료에서 시작하며 기존 로컬 제품과 검증 DB를 복제하지 않는다. 터널을 통한 제공은 컴퓨터·서버가 실행 중일 때만 가능하다.

**제안 흐름:** 서비스 진입 → SSO 인증 → 서버가 식별자와 서비스 권한 확인 → 허용된 첫 화면. SSO 프로토콜이나 실제 로그인 화면을 임의로 만들지 않는다. 필요한 권한이 없는 경우 가입 폼 대신 접근 안내를 보여주는 안이다. 최초 권한 관리자는 서버 시작 설정으로 지정한다. 실운영 복구·인수는 후속 고도화 조건이다.

대회에서는 공군 SSO 실제 연결이 불가능하므로 모의 인증 제공자를 사용한다. 로그인 전 시연 신원을 역할명으로 선택하면 모의 제공자가 단회 확인표를 발급하고 BNOC 서버가 시작 브라우저의 서버 사전 인증 상태·로그인 요청과 연결해 검증하고 일치한 요청을 소비한다. 서버는 미리 등록된 시험 식별자의 서비스 권한을 조회해 세션을 만든다. 화면에는 로그인·인증 상태만 표시하며 자체 가입·가짜 이름·계급은 없다. 실제 모의 제공자 사용 여부는 기술 문서·서버 설정·검증 기록에 남긴다. 기존 데모의 역할 선택만으로 서비스 권한을 바꾸는 동작은 이식하지 않는다. 다른 역할 시연은 로그아웃 후 다시 인증하는 안이다. 위조·만료·재사용은 거절하고 운영 모드에는 모의 인증 경로를 열지 않는다.

## 2. 요청 등록

**누가·언제:** 지원이 필요한 요청자가 신규 신청 화면에 들어온다. 시스템 사용이 어려운 요청은 BNOC가 같은 구조로 대리 입력한다. **근거:** 기존 신청 유스케이스, 사용자 결정.

| 화면 영역 | 입력·표시 | 규칙 |
| --- | --- | --- |
| 요청자 | 직접 신청은 로그인 정보, 대리는 BNOC가 선택한 실제 요청자 계정 | 서버가 활성 요청자 계정을 연결하고 등록자인 BNOC와 분리. 이름으로 계정 추정 금지 |
| 지원 유형 | 기존 유형·세부분류 | 화상회의는 KJCCS/AFCCS/웹미팅 중 하나 선택. 화상회의·일반회의 신규 신청은 해당 의뢰서 첨부 필수 |
| 요청 내용 | 내용·작업 위치·군내전화번호·선택 개인전화번호 | 군내전화는 기존 필수, 개인전화는 선택. 개인번호 공개 범위는 상세에서 제한 |
| 추가 정보 | 희망 일정 1·2지망, 장비 식별정보·관련 문서·정비대상자 정보 | 두 희망 지망은 각각 날짜와 오전/오후만 선택하며 선택 입력이다. 2지망을 입력하면 1지망도 필요하다. 실제 작업 일정이 되지 않음 |
| 첨부 | 파일 선택·진행·실패·제거 상태 | 파일 내용 저장·권한별 다운로드. 화상회의/일반회의 신규 신청은 각 의뢰서 첨부 필수 |
| 제출 | 신청 등록 | 요청·첨부 연결·이력·알림이 성공하면 요청 번호와 상세 표시 |

내용·증상 입력의 작은 안내 예문은 선택한 체계 종류·자원 유형·작업 유형 조합마다 서로 다르게 제공한다. 실제 빈도 조사 결과라고 주장하지 않는 일반 예문이며 실제 사람·전화번호·부대 자료를 넣지 않는다. 작업 위치에는 일반적인 예시를 제공한다. 이 두 입력의 예시는 입력 전 안내로 보이고 사용자가 입력을 시작하면 사라진다. 분류를 바꾸어도 이미 입력한 내용은 유지한다. 반면 선택 입력에는 입력 후에도 남는 용도·기입 예·생략 가능 안내를 제공한다. 식별정보는 알려진 자산/내선/회선번호, 문서 참조는 관련 공문 제목/문서번호이며 모르면 비워도 된다. 신규·수정·후보고에 같은 안내를 적용하고 실제 번호·문서명을 예시로 만들지 않는다. 희망 일정은 각 지망에 날짜와 오전/오후만 입력하고 실제 작업 일정이 아님을 표시한다. 필수 항목 누락·첨부 저장 실패 시 입력을 유지한다. 첨부 재시도 또는 사용자가 제거한 뒤 제출한다. 파일 제한은 [기술 설계값](개발명세서.md#technical-settings)을 따른다.

## 3. BNOC 접수·배정

**누가·언제:** BNOC가 배정 전 요청을 열고 내용을 확인한다. 필요한 문서가 없으면 기존 ‘문서 대기’를 사용한다. 하나 이상의 작업 부서를 배정한다.

| 화면 순서 | 표시·행동 | 상태 |
| --- | --- | --- |
| 요청 확인 | 요청 내용·희망 일정·자동 등록시각·문서·첨부 표시 | 기존 확정 |
| 요청 보완 | 기존에 허용된 요청 필드를 수정 | 기존 확정. 자동 등록시각은 직접 수정하지 않음 |
| 일반·긴급 | 최초 배정 폼은 일반 기본 선택. 저장 때 general/urgent 명시 전달 | 미저장 초안과 현재 분류 구분. 누락 최초 배정은 서버 거절 |
| 작업 부서 | 무선반·유선반·전장반·정체반·암호반 중 하나 이상 선택 | 기존 확정. 주·부 구분 없음 |
| 접수 시간(배정 시각) | 배정 성공 시 서버가 시각을 기록해 표시하는 안 | 시각의 의미·서버 자동 기록은 확정. 과거 시각 정정 기능 없음 |
| 배정 저장 | 일반·긴급 확인 후 부서별 ‘배정’ 작업 생성. 요청 상태·이력·알림 함께 저장 | 분류·작업·배정 시각을 한 번에 저장하는 제안. 반장 지정 제거 |

최초 배정이 성공하면 BNOC는 갱신된 요청 현황 목록으로 돌아온다. 목록은 현재 조건으로 다시 조회하고 비취소·미완료·완료 후보고 제외·유효 작업 0인 요청을 미배정 항목으로 보여줘 다음 배정을 이어서 할 수 있게 한다. 저장 실패·응답 불명확 때는 성공으로 간주해 이동하지 않고 기존 화면과 입력을 보존한다. 부서 추가·배정 변경·반환 재배정/해제는 각각 별도 카드로 표시하고, 각 명령은 기존 대상·권한·상태 조건을 따로 적용한다.

**작업 예정일 입력칸은 BNOC 배정 영역에 두지 않는다.** 희망 일정을 실제 일정으로 복사하거나 별도 승인을 추가하지 않는다. 재배정은 반환 작업에서 다른 현재 미담당 부서를 선택한다. 불필요한 반환 배정은 해제할 수 있고 미완료 요청에는 부서를 추가할 수 있다. 새 배정의 실제 일정은 미정이다.

**분류 화면:** 최초 배정은 일반 기본 선택이며 화면 진입만으로 저장하지 않는다. 성공 결과에 저장 분류·배정 부서를 함께 표시한다. 이후 현재 분류를 읽기 상태로 보여주고 변경할 때 현재값으로 편집을 시작한다. 같은 값은 재저장하지 않는다. 서버는 BNOC와 명시 분류를 검사하고 누락을 일반으로 보정하지 않는다. 네 작업 상태·일정·처리기한·수신자·정렬을 분류 변경만으로 자동 변경하지 않는다.

**최신 사용자 결정:** 배정 후에도 BNOC가 일반·긴급을 정정할 수 있다. 분류 저장은 전후 이력을 남기며 작업 상태·일정은 바꾸지 않는다. 반환 재배정에서는 기존 분류를 유지한다. 완료 후보고는 미분류로 저장하고 BNOC가 나중에 분류한다. 작업반 분류 권한·후보고 승인 단계는 없다.

최신 답변에 따라 접수 시간은 배정 시각으로 정의하고 반장 선택/입력은 제거한다. 배정 전에는 시각 입력을 강제하지 않고 성공 시 서버가 기록해 보여주는 안이다. 과거 시각을 고치는 권한은 임의로 만들지 않는다.

**작업지시:** 요청 내용 자체를 작업지시로 사용한다. BNOC는 작업 부서를 정하고 작업반은 자기 반 명부에서 담당 인원을 선택한다. 별도 지시문·반장 지정·새 승인 단계는 없다.

### 3.1 부서 추가와 반환 배정 해제

BNOC는 과거 BNOC 배정 이력과 저장된 general/urgent가 있는 미완료 요청(일반·긴급 모두)에 현재 미담당 부서를 추가한다. 신규 미배정·미분류 요청은 최초 배정으로 처리하고 추가 명령은 거절한다. 현재 유효 작업0개이지만 배정 이력이 있는 미배정 대기도 이 경로를 쓴다. 기존 분류·작업은 유지하고 새 번호는 과거 최대 작업 번호 다음으로 발급한다. 완료/취소 요청·완료 후보고에는 추가하지 않는다.

반환 작업마다 재배정과 “해당 부서 작업 불필요로 배정 해제”를 구분한다. 배정 해제는 고정 사유·행동자·시각·원래 작업/반환 사유/일정/이력을 보존하고 현재 담당에서 제외한다. 진행 중/완료 작업 삭제가 아니다. 한 반 완료·다른 반 반환에서 반환 배정을 해제하면 신청 전체도 완료다. 마지막 배정까지 해제하면 미배정 대기로 돌아가 요청자는 수정하고 BNOC는 다시 부서를 추가할 수 있다.

현재 유효 작업은 재배정/배정 해제로 해소되지 않은 작업이다. 미해결 반환은 여전히 유효하고 남은 작업에 포함한다. 현재 담당 반 중복은 서버가 거절한다. 반환 정정·재배정·해제와 부서 추가·마지막 작업 완료는 버전/요청 잠금 후 최신 상태로 검사한다. 완료가 먼저면 추가 거절, 추가가 먼저면 새 작업까지 끝나야 전체 완료다.

**배정 관리 화면 배치:** 최초 배정, 부서 추가, 직접 배정 변경, 반환 작업 재배정·해제는 각각 별도 카드로 표시한다. 하나의 관리 영역으로 합치지 않는다. 최초 배정 `assignTeams`, 과거 배정 요청의 부서 추가 `addTeams`, 반환 작업 재배정·배정 해제는 서로 다른 명령으로 유지한다. 카드를 분리해도 각 동작의 표시 조건·권한·현재 담당/상태 검사·저장 결과·이력·알림은 기존대로 유지한다.

## 4. 작업반 처리

**누가·언제:** 배정받은 작업반이 자기 작업의 상세를 연다. **근거:** 기존 작업 처리·일정 수정·상태 정정 계약.

화면 순서: 요청 내용·BNOC가 정한 일반/긴급·희망 일정 → 우리 반 작업 번호·상태 → 자기 반 명부의 담당 인원 선택 → 작업 일정 → 작업 메모 → 상태별 정보 → 저장. 작업반별 작업 상태의 내부값 `작업 중`은 사용자 화면에서 `작업 준비`로 표시한다. 요청 종합 상태와 내부 상태 저장값·전이 규칙은 바꾸지 않는다.

| 조작 | 저장 전 | 저장 후 |
| --- | --- | --- |
| 상태 선택 | 배정·작업 준비(내부값 `작업 중`)·완료·반환 중 선택만 함 | 저장을 눌러야 변경 반영 |
| 일정 입력·해제 | 선택 입력. 24시간에서 정시 시작의 1시간 시간대를 하나 이상 선택하고 연속된 시간대는 구간으로 연결한다. 비어 있으면 미정 | 해당 작업의 여러 일정 구간 변경, 이력 기록. 기존 일정은 원래 정확 시각을 보존하고 1시간으로 해석 |
| 담당 인원 선택 | 중앙 명부의 자기 반 인원을 선택. 작업일에 부재인 사람은 사유를 보이되 선택 비활성화. 여러 인원 선택 가능 | 서버가 작업일·부재 기간·소속을 재검사해 저장. 미선택 때문에 시작/완료를 막지 않음. 본인 요청 상세에는 선택 담당자의 계급·이름·등록된 군내전화만 표시 |
| 완료 선택 | 완료 메모 선택 입력 | 서버가 완료자·완료시각 기록. 선택 담당 인원과 로그인 행동자를 구별 |
| 완료에서 다른 상태 선택 | 새 상태에 필요한 정보 확인 | 현재 완료정보 해제, 이전 완료 이력 보존 |
| 반환 선택 | 반환 사유 필수. 현재 일정과 반환 전 계획 구분 | BNOC 알림·반환 대기 증가. 기존 일정은 이전 일정/이력으로 보존하고 현재 일정은 분리 |
| 반환 정정 | 재배정/배정 해제로 해결되기 전, 이전 일정 재사용 또는 일정 미정 선택 | 자기 작업 상태 정정 이력·BNOC 알림. 과거 일정 자동 복원 없음 |

## 5. 선조치 후보고

**누가·언제:** 작업반이 직접 연락받아 끝낸 작업을 기록한다. 활성 실제 요청자 계정을 반드시 선택하고 공통 필수값·실제 시작/완료 날짜와 24시간 시각·사유를 입력한다. 이름 텍스트만으로는 제출할 수 없다. 완료 메모는 선택이다. 서버가 선택된 계정에 소유된 완료 요청과 자기 작업반의 완료 작업·이력·BNOC 및 요청자 알림을 함께 저장한다. 별도 승인 단계는 없다.

## 6. 목록·상세·검색

신청 전체 상태와 현재 유효 담당/완료 반수·부서별 상태를 목록에 제공한다. 작업반은 우리 반 상태를 먼저 표시하고 과거 참여만 있으면 “현재 담당 아님 / 과거 참여”로 구분한다. 반수는 부서를 중복 제거하며 해당 반의 모든 유효 작업이 완료여야 완료 반으로 센다. 후보고는 별도 완료 기록으로 표시한다. 내 신청에는 같은 본인 요청자 열을 반복하지 않는다. 검색은 “신청 전체 상태”와 작업반 전용 “우리 반 작업 상태”를 구분한다. 부서 조건은 현재 담당 기준, 과거 참여는 별도 조건이다. 검색 버튼/Enter·초기화 한 번 규칙은 유지한다.

**기존 확정:** 검색 조건 변경 중 기존 결과 유지. 검색 버튼·Enter로 조건 적용, 초기화 시 기본 조회 한 번. BNOC 현황의 빠른 필터는 기존 즉시 적용을 유지한다. 상세에서 권한에 맞는 처리 이력·첨부를 연다.

## 8. 알림

**2026-10-26 개정:** 작업반 한 곳의 상태가 바뀌면 요청 전체 상태가 같아도 계정 연결 요청자에게 해당 반의 진행 알림을 남긴다. 같은 저장에서 전체 상태까지 바뀌면 요청자에게 같은 사건 알림을 중복 발송하지 않는다. 순수 예정일·담당 인원 수정은 알림을 만들지 않는다. 선조치 후보고는 실제 요청자 계정 선택이 필수이며 BNOC와 선택된 요청자에게 접수·완료 사실을 알린다.

**기존 확정:** 요청 등록·후보고는 BNOC, 배정은 해당 작업반, 요청 전체 상태 변화(기각 포함)는 계정 연결 요청자, 반환·반환 정정은 BNOC에게 전달한다. 대리 등록은 연결된 실제 요청자 계정으로 알리고 과거 계정 미연결 요청은 수신자를 추정하지 않는다. 메일·문자·메신저 발송 없음.

**개선 흐름:** 로그인 중 미확인 건수를 30초마다 조회하고 화면 복귀·명시 갱신에도 갱신한다. 건수 배지는 알림함 주 메뉴에만 표시하며 0건은 숨긴다. 반환 처리 대기는 BNOC의 미해결 반환 수이며 알림 열람과 무관하다. 새 알림은 수신자별 미확인 항목을 기준으로 하고 알림함에서 실제 표시한 notificationIds 집합만 확인 처리한다. 최신 페이지 조회가 과거 미표시 항목이나 나중에 도착한 알림까지 확인하지 않는다. 알림을 읽어도 업무는 해결되지 않으며 공지 읽음 확인은 추가하지 않는다. 실패 시 마지막 성공 자료·갱신 실패를 구분하고 사용자 변경/로그아웃 시 이전 맥락을 비운다.

| 취소·대체/배정 해제된 반환 | 주 집계에서는 제외, 이력 보존 | 제거된 기록으로 표시하거나 재배정 전후 작업을 중복 집계하지 않음 |
| 선조치 후보고 | 전체 할당·완료·부서별 작업 건수에 포함하고 별도 필터/출처 하위 건수도 제공 | 후보고 표시는 출처 부분집합이며 합계에 중복 가산하지 않음. BNOC의 사전 배정으로 표시하지 않음 |
| 미배정 요청 | 취소되지 않고 완료되지 않은 요청 중 완료 후보고가 아니며 현재 유효 작업이 없는 요청을 요청 건수로 별도 표시. 모든 배정 해제 뒤 대기도 포함 | 0작업을 업무 없음으로 오해하지 않게 구별 |
| 기준 시점·기간 | 서버의 같은 조회 기준으로 현재 상태를 집계 | 일·주·월은 정비 일정 조회로 구현하고 별도 기간별 처리 실적은 이번 범위에서 추가하지 않음 |

카드를 선택하면 같은 단위·조건의 목록을 보여주는 안이다. 페이지가 나뉘어도 총 항목 수와 카드 건수가 일치해야 한다. 필터 변화·상태 정정·재배정 때도 이 관계를 유지한다. 수기 건수 입력이나 BNOC의 별도 재집계 절차를 추가하지 않는다. 저장된 요청·작업을 서버가 같은 읽기 기준으로 집계하고 총건수와 페이지 목록을 반환한다.

이 공유 작업 현황은 2026-10-26 결정부터 R07 정비현황에 속한다. R01 운영 대상 정상/이상은 [UC-025](#uc-025)의 별도 외부 정보원 조회다. 정비 건수에서 장비 정상/장애를 추론하지 않는다.

### 9.2 일일 병력 현황과 명부

**2026-10-26 사용자 결정:** 과거 부서별 일일 휴가·출장·가용 입력과 지정 개인 `departmentManager` 운영 설명은 후속 설계에서 대체한다. BNOC 행정병이 전체 간부·병사 명부를 최초 수기 등록·정정한다. 명부의 소속·계급·이름·군번·선택 군내전화를 저장하고 실제 개인정보를 시연 초기 데이터로 채우지 않는다. 간부·병사 모두 총원에 포함한다.

BNOC가 휴가·외박·출장·파견·교육·기타의 시작일과 종료일을 등록한다. 화면은 선택 날짜에 겹치는 고유 인원 수를 결원으로, 총원에서 결원을 뺀 수를 현재원으로 보여준다. 겹치는 부재 기록 하나를 두 번 세지 않는다. 부서별·전체 숫자를 같은 기준으로 합산하고 미등록 명부나 조회 실패를 실제 0명으로 오인하지 않는다. 작업반은 업무에 필요한 허용 명부·현황을 조회하지만 다른 사람의 명부·부재를 수정하지 않는다. 일반 요청자는 인원 명부와 현황을 조회하지 않는다. 정비 요청의 선택 담당자 정보만 예외적으로 받는다.

### 9.3 야간 근무자 현황

**2026-10-26 사용자 결정 및 2026-10-27 조회 흐름 결정:** BNOC 행정병은 당직사관과 정보통신대대 일직사관, 각 작업반은 자기 반의 야간 근무 월표를 만든다. 중앙 명부에서 날짜별로 1명 또는 필요한 여러 명을 선택하고 변경된 날짜만 정정한다. 당직사관과 일직사관은 24시간 근무자로 일별 야간 현황에 자동 포함한다. 주·야간, 시작·종료 시각, 매일 반복 입력은 요구하지 않는다. 같은 날짜 같은 근무 자리의 동일 인원을 중복 선택할 수 없다. 부재자 선택은 사유를 보이며 비활성화한다. 월표 저장 뒤 해당 월·날짜 조회에 반영되고 과거 변경 이력을 남긴다. 작업반은 다른 반 또는 BNOC 근무표를 수정할 수 없다. 모든 로그인 역할은 오늘 근무자를 기본으로 일별·주별·월별로 확인한다. 요청자·관리자와 작업반의 타 범위 조회는 날짜·자리·작업반·계급·이름만 받고, 작업반은 자기 반 야간 편성에만 편집 정보를 받는다. BNOC는 기존 편집 정보를 받는다. 군번·연락처·부재 종류·사유는 근무자 응답에 포함하지 않는다. 중앙 명부·부재·병력 현황은 일반 요청자에게 공개하지 않는다. 미등록을 근무 없음으로 단정하지 않으며 자동 편성·빈 보고 강제는 없다.

### 9.4 GPS·CPCON·공지게시판

**사용자 결정:** GPS·CPCON은 모든 로그인 사용자가 조회한다. GPS는 외부 자동 수집·부대 공통 1~5단계이며 5단계만 양호다. CPCON은 별도 정보 종류·단계 사전·정보원 범위로 수집한다.

**공개 근거 기반 기술안과 2026-10-19 화면 결정:** CPCON 코드는 1~5를 별도 사전에서 검증하고 정보원 표시명 `CPCONⅠ급`~`CPCONⅤ급`을 수집·저장·API에서 유지한다. 공통 상단과 상황 상세에서 항목명 `CPCON`과 분리된 단계 결과는 코드 1~5에 대응하는 영문 대문자 `I`~`V`만 표시한다(예: 상단 `CPCON · V`, 상세 제목 `CPCON` 아래 `V`). 수집 전·실패·오래됨 표시는 기존 상태를 유지한다. [국내 보도자료·미국 국방부 교육의 확인 범위](../reference/조사근거.md#cpcon-public-evidence)를 구별하며 한국 공군의 전체 태세명·의미를 확인한 것으로 주장하지 않는다. 한국어 태세명·시험 단계 A/B를 만들지 않고 GPS의 5=양호를 붙이지 않는다. 적용 범위는 정보원 scopeKey를 그대로 관리하며 실제 부대명을 만들어 붙이지 않는다.

로그인 후 모든 업무 화면의 공통 상단에 GPS/CPCON 단계와 수집 상태만 간결히 표시하며 시각은 표시하지 않는다. 각 항목을 누르면 `/external-systems/gps/index.html` 또는 `/external-systems/cpcon/index.html` 정적 사이트를 새 팝업 창에서 연다. 이 페이지들은 BNOC 내부 SPA와 별도인 임시 외부 시스템 시연 화면이며 현재 세션으로 `GET /api/situation/gps` 또는 `GET /api/situation/cpcon`만 조회한다. 상황 화면은 단계·출처·적용 범위·수집 상태와 필요한 실패/오래됨 설명만 제공한다. API의 원본 기준시각·마지막 성공/시도 시각·만료 판정은 유지하지만 사용자 화면에는 시각을 노출하지 않는다. API 실패와 원본 유효시간 경과를 반영한다. 오래된 수집 정상 값을 현재 정상으로 재사용하지 않는다. 화면 출처는 GPS 정보원·CPCON 정보원으로 표시하고 모의/대회용 설명은 넣지 않는다. 실제 모의 정보 사용 여부는 기술 문서·서버 설정·검증 기록에 남긴다. 시도 전 미수집, 첫 시도 실패, 오래된 성공 값과 갱신 실패를 구별하고 수집 실패를 정상 단계로 바꾸지 않는다. GPS/CPCON 주 메뉴 탭은 두지 않으며 임시 팝업 화면은 실제 군 체계와 연동된 것으로 표현하지 않는다. 사용자 단계 수정 버튼은 없다. 시간 설정은 [기술 설계값](개발명세서.md#technical-settings)을 따른다.

**공지 사용자 결정:** 전체 로그인 사용자가 목록·본문·첨부문서를 조회한다. BNOC가 글을 올리고 BNOC 계정이면 작성자와 무관하게 제목·본문·첨부를 수정한다. 게시 종료·목록 숨김·읽음 확인·미확인자 집계는 없다.

**공지 화면·기술안:** 크기(16/20/24px)·제한된 색상·굵게·밑줄·목록을 제공한다. 붙여넣기는 허용 문서 구조로 정규화하고 기존 일반 텍스트/줄바꿈은 보존한다. 저장·재조회·공동 수정 뒤 서식/첨부를 유지한다. 비허용 HTML·스크립트·원격 자원·빈 서식 본문은 거절한다. 목록에서 제목을 선택해 본문·첨부를 연다. BNOC는 글쓰기 또는 수정에서 제목·본문·문서를 선택하고 저장한다. 검증된 첨부 연결과 게시물·수정 이력을 함께 저장한다. 성공 후 목록·본문을 갱신하며 실패 시 입력·재시도 안내를 유지한다. 다른 BNOC가 올렸어도 해당 공지에 이미 연결된 첨부는 유지할 수 있다. 새로 추가하는 임시 첨부에만 현재 업로더 소유 검사를 적용한다. 기존 첨부 제거는 현재 연결만 해제하고 과거 이력·파일은 보존한다. 문서 제한은 개발 명세의 기술값을 사용한다.

## 사용자 검토 시 확인할 부분

기존 동작을 다시 승인하라는 뜻이 아니다. 변경된 배정 입력, 요청 분류 표현, 달력, 서버 오류 처리와 새 운영 화면이 실제 업무에 맞는지 확인한다. 최신 업무 답변·기술값·후속 조건을 구별한 개정본에서 구현 재개 승인 범위를 기록한다. 구현 후에는 1280·1440 너비, 역할별 화면·직접 경로·새로고침·키보드·가로 넘침을 실제 확인한다. 제품 화면 검증은 구현 후 대상이다. 2026-10-21 이후 설계 검토는 Markdown 명세를 대상으로 한다.


## 기능 명세와 아키텍처 Markdown에서 검토하는 방법

기능별 근거와 서버 입력·반환 결과·예외는 [시스템 요구사항](시스템요구사항.md)에서, 담당 모듈의 실행 영역·호출 대상·전달 값·응답은 [아키텍처 Markdown](아키텍처설계.md)에서 확인한다. 배정·공유 작업·병력·야간·GPS·지시는 각각 별도 기능 명세이므로 기술안·실제 연동 후속 조건을 사용자 결정과 구별한다.

## 대회에서 외부 연동을 시연하는 흐름

1. 시연 운영자가 대회 모드로 BNOC 서버·DB·첨부 저장소와 모의 서버를 시작한다. 실제 공군 연결 경로는 사용하지 않는다. 문서·서버 설정·검증 기록의 모의 출처와 화면의 중립 문구를 확인한다.
2. 모의 인증 제공자에서 역할명으로 시연 신원을 선택한다. BNOC 서버가 인증 결과를 확인하고 서비스 권한을 조회해 세션을 생성한다. 권한 거절·만료·재로그인도 같은 서버 경로로 확인한다.
3. 로컬 시연 제어에서 GPS 또는 CPCON의 시험 시나리오를 선택한다. 이는 정보원 응답을 바꾸는 시연 조작이며 BNOC 업무 화면의 단계 수정 기능이 아니다.
4. BNOC 서버의 수집 작업이 종류별 응답을 받아 검증·저장한다. 화면은 서버에 저장된 값을 다시 조회해 표시한다. 모의 서버가 BNOC DB나 화면을 직접 수정하지 않는다.
5. 정상·단계 변경·정보 누락·잘못된 값·연결 실패·지연을 시연한다. GPS 성공과 CPCON 실패를 동시에 만들 수 있으며 실패한 종류만 갱신 실패로 표시한다. 팝업 화면에서 출처·상태·적용 범위를 확인한다. 시도 전 미수집, 첫 시도 실패(성공 값 없음), 오래된 마지막 값을 구별하며 시각은 화면에 노출하지 않는다.

CPCON 모의 응답은 공개 근거 기반의 별도 코드 사전과 정보원 scopeKey를 사용한다. 국내 실운영 단계명·의미·실제 정보원 범위를 확인한 것으로 주장하지 않는다. 임시 단계명·가짜 인명은 사용하지 않는다. 모의 수집·저장 검증과 실제 공군 정보원 호환 검증을 구별한다.

### 9.5 계획 정비 작업

**2026-10-21 사용자 결정 · 구현·검증 완료:** 작업반 사용자가 외부 계획 체계를 직접 확인해 제목과 달력 날짜로 작업을 등록한다. 외부 체계와 자동 연동하거나 비계획 정비 요청 데이터를 재사용하지 않는다. 새 작업은 `진행 중`으로 시작하고 선택 날짜를 최초 업무 기준일로 둔다. 기존 진행 중 작업은 기준일부터 선택한 날짜의 업무 목록에 자동 표시한다. 다음 날 같은 작업을 다시 추가하거나 날짜를 매일 기록하는 동작은 없다. 날짜를 과거로 바꿔도 그 당시 상태는 복원하지 않는다. 현재 완료된 작업은 날짜와 무관하게 진행 목록에 넣지 않고 완료 작업 관리에서 확인한다. 사용자는 수정·완료·영구 삭제를 각각 별도 행동으로 수행한다. 삭제는 작업·삭제 이력을 모두 제거하며 완료 처리로 세지 않는다. 한 작업이 여러 날짜의 업무 목록에 보여도 전체 작업 현황에서는 논리 작업 한 건으로 센다. 공유 할당·완료 집계에는 완료 선조치 후보고를 포함하며 출처별 후보고 수는 부분집합으로 중복 가산하지 않는다. 계획 정비는 별도 집계하고 전체 작업은 할당 작업과 계획 정비의 합계다.

**화면·상호작용안:** 기존 업무 화면 셸·메뉴 안에서 날짜 선택을 화면 맨 위에 두고, 그 아래에 제목 입력, 선택 날짜의 업무 목록, 완료 작업 관리를 배치한다. 이 날짜 선택 하나가 업무 목록 조회일과 새 작업의 최초 날짜를 함께 정한다. 날짜는 today가 기본이고 date-only이며 과거·오늘·미래 선택을 허용한다. 달력과 이전 날짜·오늘·다음 날짜 이동을 제공한다. 새 작업은 선택한 날짜부터 일일 목록에 나타난다. 기존 진행 중 작업은 날짜를 바꿔도 해당 기준일 이후의 목록에 계속 자동 표시되므로 날짜 추가 버튼·매일 재등록 안내를 두지 않는다. 제목에 장소를 포함하고 별도 위치·일일/주간/월간 분류는 두지 않는다. 완료 날짜 선택은 오늘 이하로 제한한다. 공유 현황의 기존 비계획 할당 작업은 그대로 두고 계획·전체 합계는 구분해 보여준다. 계획 제목은 사용자 결정에 따라 로그인 사용자 모두에게 표시한다.

**설계 보완안:** `수정`에서 제목과 최초 업무 기준일을 고친다. 완료된 항목 재개는 이번 범위에 넣지 않는다. 외부 체계 자동 대조나 별도 일일 실적 판정은 이번 범위에 넣지 않는다.

## UC-013 계획 정비 작업

- 상태: 구현·독립 검증 완료 · 2026-10-21
- 주 행위자: ACT-03 작업반 사용자
- 목적: 외부 계획 체계에서 확인한 계획 정비를 작업반이 제목·업무 날짜·상태로 관리하고, 공유 작업 현황에 비계획 정비와 함께 집계한다.
- 선행조건: 작업반 사용자가 로그인했다. 작업반 소속은 현재 세션으로 판정한다.
- 정상 흐름:
  1. 사용자가 기존 BNOC 메뉴에서 계획 정비 화면을 연다.
  2. 시스템은 날짜 선택을 화면 상단에 두고 해당 날짜의 업무 목록을 보여준다. 같은 날짜 선택은 목록 조회일이자 새 작업의 최초 업무 날짜다. 기준일 이후 진행 중인 작업은 별도 날짜 등록 없이 선택 날짜 목록에 계속 표시한다.
  3. 새 작업이면 `작업 추가`에서 제목과 달력 날짜를 입력한다. 날짜 기본값은 오늘이며 과거·미래 모두 허용한다. 입력 날짜는 작업이 일일 목록에 나타나기 시작하는 기준일이다. 저장된 작업은 진행 중으로 시작하고 현재 세션의 작업반 소유로 기록한다.
  4. 기준일 이후의 각 날짜에서 미완료 작업은 자동으로 다시 보인다. 사용자는 같은 제목을 재입력하거나 매일 날짜를 추가하지 않는다. 미래 기준일의 작업은 해당 날짜부터 미래 날짜 목록에 나타난다.
  5. 사용자는 수정, 완료, 삭제를 각각 별도 동작으로 수행한다. 수정에서 제목과 기준일을 고친다. 완료일은 오늘 또는 과거만 허용하며 작업 기준일보다 빠를 수 없다. 현재 완료된 작업은 선택 날짜가 과거여도 진행 목록에 복원하지 않고 완료 관리에서 확인하며 전체에서 한 번만 집계한다.
  6. 공유 작업 현황은 할당 작업, 선조치 후보고 부분집합, 계획 정비의 건수·목록을 제공한다. 완료 선조치 후보고는 할당·완료에 한 번 포함하고 출처별 후보고 수는 중복 가산하지 않는다. 전체 작업은 할당 작업과 계획 정비의 합계다. 기존 반환·미배정 동작은 유지한다. 계획 작업에 요청번호·요청 유형·예정 일정이 있는 것처럼 표시하지 않는다.
- 대안·예외:
  - 진행 중 작업이 없음: 작업 추가 화면에서 바로 제목·날짜를 입력한다.
  - 같은 작업이 여러 날 진행됨: 시작 기준일부터 선택 날짜까지 현재 진행 중 목록에 계속 표시한다. 날짜별 작업 복제·수동 날짜 추가·자정 상태 변경은 하지 않는다. 과거 날짜도 현재 상태를 보여주며 과거 시점 상태는 재구성하지 않는다.
  - 완료 또는 삭제: 완료는 작업 상태와 완료일을 별도로 저장해 한 건으로 집계한다. 삭제는 작업과 삭제 이력을 영구 제거하며 완료로 세지 않는다.
  - 날짜 오기입: 작업반이 수정 화면에서 최초 업무 기준일을 바꾼다. 여러 일의 별도 날짜 기록은 만들지 않는다.
  - 중복 제출·오래된 수정: 생성·제목/기준일 수정·완료의 중복 반영을 막고 오래된 버전은 거절한다. 영구 삭제는 삭제 이력을 남기지 않으므로 응답 유실 시 같은 탭에서 제출 번호와 날짜로 같은 요청을 다시 확인한다. 작업이 이미 영구 삭제되어 서버가 제출 번호 충돌을 반환하면 최신 목록을 다시 읽고, 원래 작업이 없음을 사용자가 확인한 뒤에만 새 제출을 시작한다. 미확정 생성 중에는 화면 이동을 막는다. 재시도 번호·날짜·시각만 탭 임시 저장소에 두고 제목과 로그인 식별자는 저장하지 않으며, 새로고침 뒤 제목을 다시 입력한다. 로그아웃·계정 전환 때 임시 제출 정보를 지운다.
  - 계정 또는 작업반 변경 후 예전 제출 재시도: 서버는 다른 계정에서 이미 사용된 제출 번호나 현재 작업반 소유가 아닌 저장 결과를 재생하지 않고 `OPERATION_NOT_AVAILABLE`로 거절한다. 화면은 그 임시 제출을 제거하고 제목을 비운 뒤 사용자가 현재 작업반 목록을 확인하고 다시 입력하게 한다.
  - 완료 항목 재개: 이번 설계 범위에는 포함하지 않는다.
- 후행조건: 진행 중 작업은 기준일 이후의 날짜별 업무 목록에 자동 표시되고 완료 또는 명시적 영구 삭제 뒤에는 모든 선택 날짜의 진행 중 목록에서 사라진다. 과거 날짜 선택도 과거 당시 상태를 복원하지 않는다. 공유 집계는 각 논리 작업을 한 번만 센다. 날짜별 업무 목록의 노출 수는 전체 현재 상태 건수에 더하지 않는다.
- 연결: FR-037, SR-BE-036, SR-BE-023

## UC-001 요청 등록

- 상태: 검토안
- 주 행위자: ACT-01 요청자 또는 ACT-02 BNOC
- 목적: 필요한 지원을 하나의 요청 형식으로 등록한다.
- 선행조건: 행위자가 로그인했다.
- 정상 흐름:
  1. 행위자가 새 요청을 연다.
  2. 시스템이 로그인 계정을 등록자로 기록한다.
  3. 요청자가 등록하면 시스템이 현재 로그인 세션 계정의 이름·군번 또는 식별번호·소속·계급을 요청자 정보로 가져오며 화면 입력으로 다른 계정을 지정할 수 없다.
  4. BNOC가 대신 등록하면 활성 요청자 계정 하나를 선택한다. 시스템은 계정을 실제 요청자로 연결하고 BNOC는 등록자로 기록한다.
  5. 행위자가 요청 유형(`장비/체계` 또는 `회의 지원`)을 선택한다.
  6. 요청 유형이 `장비/체계`면 체계 종류·자원 유형·작업 유형을, `회의 지원`이면 회의 유형을 선택한다(DEC-028). 화상회의면 KJCCS·AFCCS·웹미팅 중 하나를 선택한다.
  7. 행위자가 요청 내용·위치·요청자 군내전화번호를 입력하고, 필요하면 개인전화번호를 선택 입력한다. 필수값 범위는 DEC-013을 따른다.
  8. 요청자와 실제 정비대상자가 다르면 정비대상자 정보(소속·계급·이름·군내전화번호)를 따로 입력한다(DEC-027).
  9. 회의 지원의 화상회의·일반회의는 해당 지원 의뢰서를 첨부한다. 다른 요청은 필요하면 관련 파일을 첨부한다.
  10. 시스템이 내부 식별값·`101` 형식의 화면용 요청 번호·등록자·등록시각과 `대기` 상태를 저장한다. 화면에는 요청 번호를 표시한다(DEC-030).
  11. 시스템이 BNOC에게 신규 요청 등록을 체계 내부 알림으로 전달한다.
- 대안·예외:
  - 필수값 누락: 누락 항목을 표시하고 입력을 유지한다.
  - `회의 지원` 요청: 체계 종류·자원 유형·작업 유형 없이 회의 유형만으로 등록한다. 화상회의는 방식 선택이 필요하고 화상회의·일반회의는 첨부 없이는 등록할 수 없다.
  - 저장 실패: 성공으로 표시하지 않고 입력을 유지한다.
  - BNOC 대리 등록에서 활성 요청자 계정을 선택하지 않음: 등록을 거절한다.
  - 요청자가 필요한 지원을 특정하지 못하거나 체계에 접속할 수 없음: BNOC가 같은 요청 형식으로 대신 등록한다.
- 후행조건: 등록 경로와 무관하게 같은 구조의 요청 한 건이 생긴다.
- 연결: FR-001~008, FR-034~036, NFR-001~005, NFR-007, NFR-010, DEC-013, DEC-027~028, DEC-030

## UC-002 BNOC 요청 확인·수정·배정

- 상태: 확정
- 주 행위자: ACT-02 BNOC
- 목적: 요청을 확인하고 필요한 작업반에 배정한다.
- 선행조건: 요청이 `대기` 또는 `문서 대기`이고 BNOC가 로그인했다.
- 정상 흐름:
  1. BNOC가 신규 요청을 확인한다.
  2. 필요한 경우 요청 내용을 수정한다.
  3. 외부 체계의 문서 등록·확인이 필요하면 `문서 대기`로 바꾼다.
  4. 문서 확인이 끝났으면(또는 처음부터 필요 없었으면) 한 개 이상의 작업반을 선택해 배정한다.
  5. 시스템이 각 작업반의 작업을 `배정`으로 만든다. `문서 대기`는 별도 해제 조작 없이 이 배정으로 함께 끝나고, 요청 상태는 작업 상태를 반영해 자동으로 `배정`으로 계산된다.
  6. 시스템이 배정된 각 작업반에 새 작업 배정을 체계 내부 알림으로 전달한다.
- 대안·예외:
  - 여러 작업반 필요: 주·부 구분 없이 모두 배정한다.
  - 담당 범위 밖 요청: 배정 전 대기·문서 대기 요청을 사유와 함께 기각한다. 요청자에게 알리고, 배정된 작업이 있으면 기각하지 않는다(UC-023).
  - 배정 저장 실패: 일부 작업반만 배정된 결과를 남기지 않는다.
- 후행조건: 요청이 필요한 작업반에 배정되고 변경 이력이 남는다.
- 연결: FR-010~014, FR-027, FR-034~035, NFR-003, NFR-008~009

## UC-003 작업 처리

- 상태: 검토안
- 주 행위자: ACT-03 작업반 사용자
- 목적: 배정된 작업을 최소 입력으로 처리한다.
- 선행조건: 사용자의 작업반에 작업이 배정돼 있다.
- 정상 흐름:
  1. 사용자가 배정 내용을 확인한다.
  2. 사용자가 `배정`·`작업 준비`(내부 저장값 `작업 중`)·`완료`·`반환` 중 의도한 상태를 선택한다.
  3. 필요하면 일정·짧은 메모를 입력하고, `반환`을 선택했으면 반환 사유를 입력한다.
  4. 사용자가 `저장`을 선택한다. 상태 선택만으로는 변경하지 않는다.
  5. 시스템이 변경 전후 상태를 이력에 남기고 요청 종합 상태를 다시 계산한다.
  6. `완료`로 바꿀 때 시스템이 완료 처리자·완료시각을 자동 기록하고, 사용자는 선택적인 짧은 완료 메모를 남긴다.
- 대안·예외:
  - 오판단·상황 변경·오조작: 재배정으로 대체되지 않은 작업은 현재 상태보다 앞이거나 뒤인 상태로 다시 저장할 수 있다.
  - `완료`에서 다른 상태로 정정: 현재 완료정보를 제거하되 기존 완료 이력은 유지한다. 다시 완료하면 새 완료정보를 기록한다.
  - 담당 밖 작업: `반환`과 사유를 함께 저장하고 UC-005를 이어간다.
  - 재배정으로 대체된 반환 작업: 기존 작업의 상태 정정을 거절하고 새 재배정 작업을 표시한다.
  - 일정 변경: 일정만 수정하며 별도 지연 상태를 만들지 않는다.
  - 동시 수정: 최신 내용을 보여주고 오래된 변경으로 덮어쓰지 않는다.
- 후행조건: 작업 상태·일정·메모·변경 이력이 일치한다.
- 연결: FR-014~020, FR-027~028, NFR-003, NFR-005, NFR-008~009, DEC-032

## UC-004 복수 작업반 처리

- 상태: 확정
- 주 행위자: ACT-02 BNOC, ACT-03 작업반 사용자
- 목적: 한 요청을 여러 작업반이 동등하게 처리한다.
- 선행조건: 요청이 두 개 이상의 작업반에 배정돼 있다.
- 정상 흐름:
  1. 각 작업반은 자기 작업의 상태·일정·메모를 따로 기록한다.
  2. 요청자는 하나로 합쳐진 상태 대신 배정된 작업반별 작업 상태를 각각 확인한다.
  3. 일부 작업반만 완료됐으면 요청은 완료되지 않는다.
  4. 반환 문제가 없고 모든 배정 작업이 완료되면 요청을 `완료`로 표시한다.
- 대안·예외:
  - 한 작업반 반환: 다른 작업반의 기록은 유지하고 반환 건만 UC-005로 처리한다.
- 후행조건: 주·부 구분 없이 모든 작업반 결과가 요청 상태에 반영되며, 요청자는 작업반별 진행 상황을 구분해 확인할 수 있다.
- 연결: FR-012~017, FR-021, FR-024, NFR-008~009

## UC-005 작업 반환·재배정

- 상태: 검토안
- 주 행위자: ACT-03 작업반 사용자, ACT-02 BNOC
- 목적: 잘못 배정된 작업을 사유와 함께 돌려보내고 다시 배정한다.
- 선행조건: 작업반에 `배정`·`작업 중`인 작업이 있거나, 같은 작업반이 재배정 전인 미해결 `반환` 작업을 정정하려 한다.
- 정상 흐름:
  1. 작업반 사용자가 반환 사유를 입력한다.
  2. 시스템이 해당 작업을 `반환`으로 저장한다.
  3. 다른 작업이 진행 중이지 않으면 요청 상태를 `대기`로 표시한다.
  4. 시스템이 BNOC에게 작업 반환을 체계 내부 알림으로 전달한다.
  5. BNOC가 반환 사유를 확인한다.
  6. BNOC가 적절한 작업반에 다시 배정한다.
  7. 시스템이 요청 안에서 중복 없는 `101-1` 형식의 작업 참조값을 가진 새 작업을 `배정`으로 만들고 반환된 기존 작업을 완료 계산에서 제외한다.
- 대안·예외:
  - 적절한 작업반을 바로 정하지 못함: 요청을 `대기`로 유지한다.
  - 반환 오조작을 재배정 전에 발견함: 원래 작업반이 UC-003에 따라 필요한 상태로 정정하고 시스템이 BNOC에 반환 정정 알림을 남긴다.
  - BNOC가 이미 재배정함: 기존 반환 작업의 상태 정정을 거절하고 새 재배정 작업으로 처리한다.
- 후행조건: 해결되지 않은 반환이 남아 있으면 요청은 완료되지 않는다.
- 연결: FR-015, FR-017, FR-021, FR-027, FR-033~035, NFR-008~009

## UC-006 요청 수정

- 상태: 확정
- 주 행위자: ACT-01 요청자
- 목적: 아직 작업이 시작되지 않은 본인 요청의 내용을 바로잡는다.
- 선행조건: 요청자가 본인 요청을 열었다.
- 정상 흐름:
  1. 요청자가 본인 요청의 수정을 선택한다.
  2. 시스템이 배정된 작업이 아직 `작업 중`이 되기 전인지 확인한다.
  3. 요청자가 허용된 요청정보를 바꿔 저장한다.
  4. 시스템이 변경자·시각·변경 항목을 이력에 남긴다.
- 대안·예외:
  - `작업 중` 이후 또는 기각 요청 수정 시도: 수정을 거절하고 현재 상태를 보여준다.
  - 이미 다른 사용자가 변경함: 최신 내용을 보여주고 다시 선택하게 한다.
- 후행조건: 요청과 변경 이력이 함께 저장된다.
- 연결: FR-009, FR-027, NFR-003, NFR-008~009, DEC-025

## UC-007 요청 취소

- 상태: 확정
- 주 행위자: ACT-01 요청자
- 목적: 더 이상 필요 없는 본인 요청을 현재 상태와 무관하게 중단한다.
- 선행조건: 요청자가 본인 요청을 열었다.
- 정상 흐름:
  1. 요청자가 본인 요청의 취소를 선택한다.
  2. 시스템이 현재 상태와 무관하게 요청을 `취소`로 표시한다.
  3. 취소 시점에 진행 중이거나 배정돼 있던 작업은 더 이상 진행하지 않는다.
  4. 시스템이 취소자·시각을 이력에 남긴다.
- 대안·예외:
  - 이미 다른 사용자가 변경함: 최신 내용을 보여주고 다시 선택하게 한다.
- 후행조건: 요청과 변경 이력이 함께 저장된다. 기각 요청은 취소할 수 없고 `재개` 행동도 두지 않는다.
- 연결: FR-009, FR-027, FR-033, NFR-003, NFR-008~009, DEC-025

## UC-008 요청 진행 확인

- 상태: 확정
- 주 행위자: ACT-01 요청자
- 목적: 현재 처리 단계를 직관적으로 확인한다.
- 선행조건: 요청자가 본인 요청을 열었다.
- 정상 흐름:
  1. 요청자가 요청 목록이나 상세를 연다.
  2. 시스템이 `대기`, `문서 대기`, `배정`, `작업 중`, `완료`, `취소` 중 현재 상태를 표시한다.
  3. 배정 작업반과 일정이 있으면 함께 표시한다.
  4. 내부 처리정보와 다른 사용자의 개인정보는 표시하지 않는다.
- 대안·예외:
  - 정보 없음: 없는 값을 임의로 채우지 않는다.
- 후행조건: 요청자가 추가 문의 없이 현재 단계를 이해할 수 있다.
- 연결: FR-024~025, FR-030~033, NFR-004, NFR-006

## UC-009 요청 검색·이력 조회

- 상태: 검토안
- 주 행위자: ACT-02 BNOC, ACT-03 작업반 사용자
- 목적: 현재 요청과 과거 처리 기록을 찾는다.
- 선행조건: 사용자가 로그인했다.
- 정상 흐름:
  1. 사용자가 허용된 임시 검색조건(기간·상태·업무 유형·작업반·위치·화면용 요청 번호, BNOC는 요청자 소속·이름도 가능)을 입력한다. 입력·선택 중에는 현재 결과가 바뀌지 않는다.
  2. 사용자가 `검색` 버튼을 선택하거나 검색 입력에서 Enter를 실행한다.
  3. 시스템이 임시 검색조건을 적용 검색조건으로 바꾸고 권한 범위 안의 결과를 한 번 조회해 표시한다.
  4. 사용자가 요청 상세와 변경 이력을 확인한다.
- 대안·예외:
  - 결과 없음: 검색조건을 유지하고 빈 결과를 표시한다.
  - 권한 밖 요청: 존재 여부와 내용을 노출하지 않는다.
- 후행조건: 사용자는 권한 범위 안의 요청과 이력만 본다.
- 연결: FR-025~027, NFR-003~004, NFR-012, DEC-030~031

## UC-010 일정·처리 현황 조회

- 상태: 확정
- 주 행위자: ACT-02 BNOC, ACT-03 작업반 사용자
- 목적: 처리할 요청과 작업 일정을 빠르게 확인한다.
- 선행조건: 사용자가 로그인했다.
- 정상 흐름:
  1. 작업반 사용자는 자기 작업반의 배정 작업과 일정을 확인한다. 선택 기간 안 같은 작업은 한 카드에만 표시하고, 조회 기간과 겹치는 가장 이른 시작 시각 순으로 배치한다. 그 카드에는 기간 안의 모든 작업 구간을 함께 보인다.
  2. BNOC는 기간·상태·작업반·요청 유형별 요청 건수와 목록을 확인한다.
  3. 작업반 일정에는 선조치 후보고 완료 기록도 포함한다. 실제 시작 시각을 기준으로 카드 한 장만 배치하고 정확한 시작 시각을 보인다. 계획 구간이 기간과 겹치는 완료 작업은 그 계획 시작 시각에 카드 한 장으로 표시하고 실제 완료 시각도 함께 보인다.
  4. 사용자는 일정 카드 전체 또는 목록에서 허용된 요청 상세로 이동한다. 상세 접근 권한을 다시 확인한다.
- 대안·예외:
  - 결과 없음: 선택한 조건을 유지하고 빈 화면을 표시한다.
- 후행조건: 사용자에게 필요한 범위의 일정과 현황만 표시된다.
- 연결: FR-025, FR-028~029, NFR-004

## UC-011 작업반 선조치 후보고

- 상태: 검토안
- 주 행위자: ACT-03 작업반 사용자
- 목적: 직접 연락받아 먼저 끝낸 작업을 사후에 기록한다.
- 선행조건: 작업반이 요청을 직접 받아 작업을 실제로 완료했다.
- 정상 흐름:
  1. 작업반 사용자가 선조치 후보고를 연다.
  2. 실제 요청자를 텍스트로 입력한다.
  3. 요청 유형(`장비/체계` 또는 `회의 지원`)을 선택하고, 유형에 따라 체계·자원·작업 유형 또는 회의 유형을 선택한다. UC-001과 같은 필수값 구성을 따른다(E-025).
  4. 요청 내용·증상 입력에는 선택 조합별 일반 예문을, 작업 위치에는 일반 예시를 입력 전 안내로 표시한다. 입력 시작 후 안내는 사라지고 사용자의 값은 보존한다. 요청 내용, 작업 위치, 필요한 군내전화번호를 입력한다.
  5. 요청자와 실제 정비대상자가 다르면 정비대상자 정보(소속·계급·이름·군내전화번호)를 입력한다.
  6. 선택적으로 짧은 완료 메모를 입력한다.
  7. 시스템이 내부 식별값과 중복 없는 `101` 형식의 화면용 요청 번호를 가진 요청과 `101-1` 형식의 작업 참조값을 가진 현재 로그인 세션 작업반의 완료된 작업을 함께 만든다. 화면 입력으로 다른 작업반을 지정할 수 없다.
  8. 시스템이 등록자·등록시각·완료 처리자·완료시각을 자동 기록하고 화면에는 요청 번호를 표시한다.
  9. 시스템이 BNOC에게 선조치 후보고 등록을 체계 내부 알림으로 전달하고, BNOC가 요청 번호로 후보고를 조회할 수 있게 한다. 이 작업은 출처를 `선조치 후보고`로 유지하면서 전체 공유 현황의 할당·완료 및 부서별 작업 건수에 한 번 포함하고, 현재 작업반 일정에는 실제 시작 시각이 속한 한 시간 칸의 완료 기록으로 표시한다.
- 대안·예외:
  - 아직 작업이 끝나지 않음: 후보고 요청·완료 작업을 만들지 않고 입력을 유지한다. 작업반 사용자는 일반 요청 등록 권한이 없으므로 BNOC 역할로 전환한 뒤 유지된 입력을 UC-001의 BNOC 대리 등록으로 제출해 배정을 받는다.
  - 중복 제출: 같은 후보고를 다시 만들지 않는다.
  - 저장 실패: 요청과 작업 어느 쪽도 일부만 남기지 않는다.
- 후행조건: 요청과 완료 작업이 연결되며 별도 승인 단계 없이 이력이 남는다. 완료 후보고는 배정·완료 합계에 포함되며 별도 하위 건수는 부분집합이다. 일정 카드에는 정확한 실제 시작 시각, 작업번호와 완료 상태, 위치·작업 메모를 표시하며 전화번호·요청 상세는 제외한다.
- 연결: FR-004~007, FR-020, FR-022~023, FR-027, FR-035, NFR-007~009, DEC-013, DEC-026~027, DEC-030

## UC-012 역할·작업반 권한 관리

- 상태: 안전 기본
- 주 행위자: ACT-04 권한 관리자
- 목적: 사용자에게 필요한 역할과 작업반 권한만 부여한다.
- 범위 참고: 대회 웹 데모는 이 유스케이스의 로그인 화면을 제공하지 않는다(DEC-011). 데모용 계정과 권한은 사전에 구성된 상태로 제공한다. 이 유스케이스는 실제 운영(공군 인트라넷) 요구사항으로 유지한다.
- 선행조건: 권한 관리자가 로그인했다.
- 정상 흐름:
  1. 권한 관리자가 사용자를 선택한다.
  2. 역할 또는 작업반 소속을 부여·회수한다.
  3. 시스템이 권한 변경과 변경 이력을 함께 저장한다.
  4. 변경된 권한을 다음 요청부터 적용한다.
- 대안·예외:
  - 자기 권한 상승: 거절한다.
  - 동시 변경: 최신 권한을 보여주고 오래된 변경을 거절한다.
  - 권한 관리자 계정 분실·오설정 때 복구 절차: DEC-015 미정. 지금 단계에서는 다루지 않는다.
- 후행조건: 실제 권한과 변경 이력이 일치한다.
- 연결: FR-025, FR-027, NFR-002~004, NFR-008~009, DEC-015
